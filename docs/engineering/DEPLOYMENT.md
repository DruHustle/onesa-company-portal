# Deployment and independent releases

<!-- onesa-protected-source: portal-deployment -->

## Primary release path

The frontend, backend and billing components in the [Portal repository](https://github.com/DruHustle/onesa-portal) have independent releases. Identify the component and source revision, verify the required checks, and record the outcome of its staging qualification. The release owner authorizes promotion and verifies the affected workflow against the serving component.

Track component-specific release evidence using the [release checklist](../../RELEASE_CHECKLIST.md) and [qualification reference](AUTOMATED_QUALIFICATION.md). A documentation update does not deploy an application.

Authorized operators can obtain installation, verification and recovery procedures through [Onesa Internal Documents](https://docs.internal.onesa.eu). Use the approved procedure for the component and environment selected by the release owner.
